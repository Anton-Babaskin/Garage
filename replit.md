# Гараж — инструкция для агента (читать перед любой правкой)

Ты обслуживаешь рабочий сайт, которым **каждый день** пользуются 4 водителя (40+, не айтишники) и руководство компании в Стамбуле.
Главное правило: **сайт не должен падать и данные не должны пропадать.** Лучше маленькая точная правка, чем красивая переделка.

Владелец — Антон (инженер Linux/инфраструктуры). Пишет по-русски, коротко. Отвечай по-русски, сначала решение, потом объяснение.

## Что это

Учёт 4 машин: где стоит, у кого ключи, пробег, передачи между водителями, замечания, ТО, мойки, карта паркингов.

- Рабочий домен: `autozxc.app`. Публикует владелец самостоятельно.
- Машины: BMW iX (34 ML 5050), Audi A6 (34 HRZ 549), Fiat Egea (34 GRA 342), Škoda Superb L&K (34 MDH 491).
- Паркинги: Вади, Терас, Чамлы (+ «Сервис», «Другое»).
- Пользователи: водители `d1`–`d4` (Эркин, Озгюр, Мурат, Водитель 4), `manager` (Руководитель) и `darya` (Дарья) входят по паролю; до его назначения подходит старый PIN.
  `anton` (Антон) — без изменений: PIN 6 цифр и секрет ADMIN_PIN.
- Пароль — любой непустой текст, без проверки сложности, повторного поля, подсказок и обязательной смены. Хранятся только соль и scrypt-хэш; пароль не попадает в логи или открытые файлы.
- Сессии: `SESSION_DAYS`, по умолчанию 365 дней; каждое авторизованное обращение продлевает срок и cookie `gsid`. Новый пароль завершает все сессии человека.
- Сайт закрыт от посторонних: `SITE_KEY` — секрет из 12 латинских букв/цифр; ссылка `/?k=…` выдаёт HttpOnly/Secure/SameSite=Lax cookie `gk` на 365 дней и убирает ключ из адреса. Смена секрета отключает старые ссылки и `gk`; действующие `gsid` сохраняют доступ. Без доступа на любой путь — обычный текстовый 404, исключения только `/healthz` и `/robots.txt`. Manifest динамический и закрытый, start_url содержит ссылку доступа для iPhone.
- Экран входа без названия, логотипа и списка людей: только логин, пароль, «Войти», RU/TR; заголовок вкладки «Вход». Логины без учёта регистра: `erkin` → d1, `ozgur` → d2, `murat` → d3, `driver4` → d4, `manager`, `darya`, `anton`. Антон вводит свой PIN в общее поле пароля; ADMIN_PIN и scrypt не менять. Ошибка входа одна: «Неверный логин или пароль». Список пользователей API отдаёт только после входа. Готовую ссылку доступа руководство копирует через имя вверху справа → «Ссылка доступа»; ключ не записывать в код, файлы или логи.
- Не индексировать: `X-Robots-Tag: noindex, nofollow` на всех ответах, meta robots в HTML и `/robots.txt` с `Disallow: /`.
- Первый выезд доступен водителю без начальных данных от руководства: в форме пробег 0, водитель может указать текущее показание. При парковке вводятся фактический пробег, место и ключи; далее используется последнее показание. Старый журнал не изменяется.
- **Два языка обязательно: русский и турецкий.** Язык выбирается по телефону, переключается кнопкой. Любой новый текст — на обоих языках.

## Как устроено

```
server.js        HTTP-сервер на чистом Node.js: вход по паролю / PIN, сессии, API, статика, резервные копии
core.js          ЯДРО: правила учёта (журнал событий). Общее для браузера и сервера — сервер проверяет им каждое действие
public/
  index.html     оболочка страницы (почти пустая, всё рисует ui.js)
  ui.js          весь интерфейс (vanilla JS, без фреймворков). Вверху APP_VERSION
  i18n.js        турецкий словарь TRD: ключ = точный русский текст из T('…'), значение = перевод
  app.css        стили (дизайн-токены в :root)
  map.js         контуры районов Стамбула для карты (не редактировать руками)
  photos.js      фото машин base64 (не редактировать руками)
  env.js         флаг серверной версии
test/smoke.js    проверка перед публикацией: npm test
```

**Данные — журнал событий** (`state.events`): взял, передал, принял, поставил, ключи, замечание, исправил пробег (`odo_fix`), мойка (`wash`)…
Текущее состояние машин **вычисляется** из журнала функцией `project()` в core.js. Журнал никогда не переписывается — только дополняется.

**Хранилище:** если есть `DATABASE_URL` → PostgreSQL, таблица `garage_kv` (ключи `state.json`, `users.json`, `sessions.json`, `backup:*`). Иначе — файлы в `DATA_DIR`.
На Replit у **превью (workspace) и опубликованного сайта разные базы**: правки в редакторе не трогают рабочие данные.

**Клиент ↔ сервер:** браузер сначала проверяет действие тем же core.js (мгновенный ответ + ошибки на нужном языке), потом шлёт `POST /api/op {op, args}`.
Сервер сам ставит автора (по сессии) и время. Телефоны раз в 15 с опрашивают `GET /api/state?v=N`.

## Железные правила

1. **Никогда не удаляй и не пересоздавай данные.** Нельзя: `DROP`, `TRUNCATE`, `DELETE FROM garage_kv`, перезапись `state.json`, «сброс базы», «seed», демо-данные, миграции, которые стирают журнал.
2. **Рабочие данные меняют в интерфейсе сайта, не в коде.** Пробег, PIN, имена водителей, номера машин, точки паркингов, интервалы ТО — это делает руководство на опубликованном сайте. Если просят «поставь BMW пробег 185 000» — ответь, где нажать (см. «Частые просьбы»), **не хардкодь числа в код**.
3. **Маленькие точечные правки.** Не переформатируй файлы, не переименовывай функции, не переписывай модули «для чистоты». Меняй только то, что нужно для задачи.
4. **Без новых зависимостей и сборщиков.** Никаких React/Vite/TypeScript/Tailwind/npm-пакетов. Единственная зависимость — `pg`.
5. **Каждый видимый текст — через `T('Русский текст')`**, и в `public/i18n.js` (объект `TRD`) — строка `"Русский текст": "Türkçe metin",`. Имена людей и паркингов в турецкой версии подменяет `dn()` (список `NAMES` в i18n.js).
6. **Обратная совместимость журнала.** Старые события должны проигрываться в `project()` как раньше. Новые правила — только для новых событий. Не меняй смысл существующих `kind`.
7. **Не ослабляй защиту:** хэш пароля / PIN (scrypt), существующая блокировка перебора без новых ограничений, cookie `HttpOnly/Secure/SameSite`, проверка заголовка `X-Garage`, CSP (`script-src 'self'` — без inline-скриптов и `onclick=`), роли в `OPS` (server.js) и в core.js. Не выводи пароли и PIN в логи.
8. **Интерфейс для людей 40+:** крупные кнопки (≥44px), мало цвета, понятные слова. Основной экран — телефон 390px. Руководителю — спокойный вид (класс `calm`), водителю — простой (класс `drv`).
9. **Не убирай существующие функции** без прямой просьбы.
10. **После каждой правки:** подними `APP_VERSION` в `public/ui.js` на 1, добавь строку в `CHANGELOG.md`, запусти **`npm test`** — должно быть «✓ Всё в порядке». Только потом Publish/Redeploy. Если тест красный — чини, не публикуй.

## Частые просьбы → что делать

| Просьба | Ответ / действие |
|---|---|
| Поменять / исправить пробег | **В интерфейсе:** войти руководством → Машины → машина → «Исправить пробег» (новое число + причина). Машина должна стоять на паркинге. Код не трогать |
| Первый пробег машины («Нет данных») | Водитель: «Мой экран» → машина → «Взять» (пробег 0, можно уточнить) → «Поставить на паркинг» и фактический пробег. Руководство по-прежнему может заранее «Внести данные» |
| Человек забыл пароль / старый PIN | Руководство: имя вверху справа → нужный человек → «Задать пароль» → одно поле → Сохранить; сообщить лично |
| Антон не может войти | Secrets → `ADMIN_PIN` (6 цифр) → Redeploy: PIN Антона станет этим |
| Переименовать водителя | Водители → «Имя» |
| Номер / модель / фото машины | Машины → машина → «Модель и номер» |
| Точка паркинга на карте | Ещё → Паркинг → «Изменить точку» (координаты или ссылка Google Maps) |
| Через сколько часов «поездка не закрыта» | Водители → Напоминания → Настроить |
| Добавить вид мойки (полировка, мойка двигателя…) | `core.js` → массив `WASH_TYPES` (новая строка `{id:'polish',name:T('Полировка')}`) + перевод в `public/i18n.js`. Старые записи не трогать |
| Мойки — где | Водитель: вкладка «Мойки» или кнопка «Записать мойку» на «Мой экран». Руководство: Ещё → Мойки, или карточка машины → «Мойка» |
| Выгрузить журнал | Журнал → «Открыть таблицей» → Google Таблицы / CSV |
| Копия данных | Водители → «Сохранить копию» (JSON). Восстановить — там же |
| Поменять текст / кнопку | `public/ui.js` + перевод в `public/i18n.js` |
| Новое правило учёта | `core.js` (влияет и на сервер, и на браузер) + перевод ошибок |
| Пятый водитель / новая машина | Это изменение структуры (в core.js жёстко 4 водителя `d1–d4` и 4 машины `CARS`). Сначала опиши Антону план и риски, правь только после «да» |

## Где что в коде (быстрый поиск)

- Экраны: `viewCars` (главный руководителя, на ПК → `viewDash`), `viewMine` (водитель), `viewJournal`, `viewStats`, `viewService` (ТО), `viewTeam` (Водители), `viewPark` (карта), `viewWash` (мойки). Вкладки — `tabs()`, меню «Ещё» — `moreSheet()`.
- Шторки (формы): `carSheet`, `actionSheet` (взять/поставить/передать), `odoFixSheet`, `keysSheet`, `issueSheet`, `svcSheet`, `placeSheet`, `accountSheet`, `pinSheet`, `washSheet`.
- Клики: один обработчик `document.addEventListener('click', …)` → `switch(a)` по `data-act`. Формы: обработчик `submit` → `form==='…'`.
- Вход и синхронизация: блок «v20: серверная версия» в ui.js (`srvBoot`, `renderLogin`, `srvPush`, `srvPull`).
- Правила: `project()` и `transact()` в core.js; напоминания — `attention()`.
- API: `server.js` → `OPS` (что можно водителю, что только руководству), маршруты `/api/*`.

## Проверка руками (после заметных правок)

1. Открыть сайт **в новой вкладке** (во встроенном превью Replit вход может не работать из-за cookie; для превью запуск уже с `ALLOW_FRAME=1 COOKIE_SAMESITE=None`).
2. Войти водителем → взять машину → поставить. Войти руководством → увидеть изменение.
3. Переключить язык (Türkçe) → нет русских слов.
4. Узкий экран 390px — ничего не вылезает.

## Если что-то сломалось на рабочем сайте

1. Откатить код: в чате агента — вернуться к предыдущему checkpoint (Rollback), затем Redeploy. Данные в базе при откате кода не трогаются.
2. Логи: Deployments → Logs (входы, ошибки, строки `audit`).
3. `GET /healthz` → `{"ok":true,"v":N}`.
4. Резервные копии: строки `backup:state-ГГГГ-ММ-ДД` в `garage_kv` (60 последних). Восстановление — только через интерфейс («Восстановить копию») и только по просьбе Антона.
